# Design decisions

Short records of choices made so far, and why. Newest last.

1. **GPS goes up over REST, not the WebSocket.** `POST /location` gets auth middleware, validation, rate limiting and retries for free. Sockets are only for fan-out to students (Phase 4).
2. **Staleness is measured with the server's receive time**, never the phone's clock. A phone with a wrong clock can't make a dead bus look live.
3. **The bus comes from the driver's active trip**, never from the request body. A driver can't report for another bus.
4. **The database enforces one active trip per bus and per driver** (partial unique indexes), so races can't create duplicates.
5. **A stop is stored once per pass** (`route_stops`). The route is an out-and-back on one road, so direction = position along the whole loop, not GPS heading.
6. **Snapping uses the previous progress to pick the leg.** The two legs are only a few metres apart, closer than phone GPS accuracy, so geometry alone can't tell them apart. Consequence: trips start at DG Corner.
7. **Sign-in sat behind one function (`requireDriver`) from the start**, first as a dev header, now as real JWT checks (see 23-29). The routes didn't change.
8. **The browser talks to one origin (`/api`, proxied by Vite).** No CORS, and an https page on a phone isn't blocked as mixed content. Production uses `VITE_API_URL`.
9. **The driver page sends the newest fix every N seconds and does not queue old ones.** The server rejects fixes older than 5 minutes, and a stale queue would delay fresh data. Gaps while offline stay gaps in the history.
10. **Fixes with accuracy worse than 100 m are shown to the driver but not sent.** The same limit is enforced by the server.
11. **Client-side progress/direction is interim.** The student page snaps fixes itself in Phase 3; Phase 6 moves it to the server so ETA and direction come from one place.
12. **A web page can't track in the background.** The driver page keeps the screen on (Wake Lock) and warns before closing. If this proves unreliable in the field, the next step is a small native wrapper or a hardware tracker, not more web tricks.

13. **Live updates: REST for state, WebSocket for change.** The page loads `/buses`, then patches it from Socket.IO events, and refetches on every (re)connect and every 30 s as a safety net, so a dropped event can never leave it wrong for long.
14. **A silent bus must visibly go stale.** If a driver loses signal nothing is sent, so no event can say so. The page therefore re-derives status and "last updated" every second from thresholds served by `GET /config`.
15. **"How old is this fix" is measured on one clock.** The server reports each fix's age; the browser adds the time elapsed on its own clock since it heard that. Comparing the server's timestamp with the phone's clock would show a live bus as stale on any phone whose clock is off.
16. **Redis is an accelerator, not a dependency.** Fan-out and the cached latest fix use it when it is ready; when it isn't, the API answers from Postgres and events go straight to this instance's clients. Calls skip Redis instead of waiting for it to time out. The subscriber re-subscribes on every reconnect.
17. **Markers glide in JS, not CSS.** A CSS transition on Leaflet's transform also slides markers during zoom, and rebuilding the icon each render made them blink.

18. **The server computes route progress, direction and ETA; the browser only displays them.** Every client (student page, a future notification or admin view) then agrees. Progress is stored with each fix (`route_progress_m`, `off_route_m`, `speed_est_mps`) and pushed in the WebSocket event, so a page needs no route maths and the history is ready for ETA improvements.
19. **ETA is deterministic: distance / cruising speed + dwell per stop.** The speed is smoothed from moving samples only, so waiting at a stop doesn't make the bus look slow; stops are accounted for by the dwell term. Machine learning is deliberately not used until there is history to learn from.
20. **No ETA from stale or off-route data.** A bus that is more than 2 minutes silent, or more than 30 m from its route, gets no ETA. An ETA built on a position that old would be a promise nobody can keep.
21. **"Just passed" is a first-class answer.** For a stop the bus passed within 60 m, the student sees that, plus when the next pass comes (the return leg), instead of a confusing countdown of a whole lap.
22. **Route data is cached per process for 5 minutes** (`RouteModelCache`). Routes change rarely; a failed lookup skips progress/ETA for that fix but never blocks storing it.

23. **Access token in memory, refresh token in an httpOnly cookie.** A script injected into the page can read `localStorage` but not an httpOnly cookie, and an access token that only lives in a variable is gone on reload (restored silently from the cookie). The 15-minute access token limits what a leaked one is worth.
24. **Refresh tokens rotate, and reuse revokes everything.** Each use trades the token for a new one. Presenting an already-used token means a copy exists somewhere, so all of that user's sessions end. Two browser tabs refreshing at the same instant look the same, so a 10-second grace window turns that race into a plain refusal and the retry (with the newer cookie) succeeds.
25. **Cookie endpoints need a custom header (`X-Requested-With`), and the cookie is `SameSite=Lax`.** A page on another site can neither send the header (without a CORS preflight the server refuses) nor attach the cookie to a cross-site POST. Cookie `Path=/`, because behind a proxy the browser's path differs from the server's.
26. **Role and active status are read from the database on every request, not trusted from the token.** Disabling a driver or changing a role takes effect immediately, not when the token expires. It costs one primary-key lookup per request.
27. **Passwords use scrypt from Node's standard library.** No native module to compile on Windows or a free host. Parameters are stored in each hash so they can be raised later. Unknown email, wrong password and disabled account give the same answer in the same time (a dummy hash is checked), so accounts can't be discovered.
28. **A driver can only start trips on buses assigned to them** (`driver_buses`). Together with "the bus comes from the active trip" (3), a driver cannot report positions for anyone else's bus.
29. **Login attempts are limited in memory** (per account+IP and per account). That is enough for one instance and is replaced by Redis-backed limits in Phase 9 with the rest of the rate limiting. Dev passwords exist only outside production, and production refuses to start without a real `JWT_SECRET`.

30. **Stop passes are computed by the server whenever a route or a stop changes.** Phase 3's `stop-progress.mjs` computed them once by hand; now `analyzeRoute` does it for every edit, in the same transaction, so the numbers ETA depends on can't go stale. A test checks it reproduces the hand-computed values exactly.
31. **Which stops belong to a route is geometry, not a checklist.** A stop within 15 m of the line is on the route. One less thing to maintain and nothing to forget; the Stops page shows any stop that is on no route.
32. **Routes are entered as pasted points, with a mandatory preview.** The admin already traces routes on geojson.io. GeoJSON (longitude, latitude) is converted; plain lists are latitude, longitude. A swapped pair stays in range for Varanasi, so the check is the preview: its warning when no stop is near the path, and the map.
33. **Things that would break a running trip are refused, not allowed with a warning.** Changing a path under a bus, switching a route off, or disabling a bus mid-trip all return 409; the admin ends the trip first (or force-ends it). Deleting anything with trip history is refused in favour of disabling, so history stays whole.
34. **An admin can't lock themselves out.** Self-disable, self-demote and self-delete are refused, so there is always an admin who can fix things.
35. **Generated passwords are shown once.** The server returns a generated password in the response to the admin who made the account and stores only the hash. Resetting a password or disabling an account also ends that person's sessions.
36. **Every admin change goes in an audit log**, with the actor's name copied in so entries survive the account being deleted. Passwords are never written to it.
37. **Driver and admin screens load only when opened.** Students download the map and nothing else, which matters on a phone on campus Wi-Fi.

38. **Rate limiting is shared through Redis and never depends on it.** Counters use Redis when it is healthy (so several servers agree) and memory when it isn't, so a Redis outage can't turn into an API outage. A counter that somehow has no expiry is repaired rather than blocking someone forever.
39. **Limits are different for different risks.** Wrong passwords are counted per (address, account) so one person's typos don't lock out others, plus a looser per-account cap against guessing from many addresses. `POST /location` is capped per driver, admin changes per admin. The general per-address cap is high on purpose: a campus can put hundreds of students behind one address.
40. **Logs can't leak secrets, because they never contain them.** Headers, cookies, bodies and query strings are not logged at all; a redaction rule is only a second net. Every response carries a request id the user can quote, and the same id is in the logs and the error report.
41. **Errors reach a person, not just a log.** Optional Sentry for unexpected 5xx and crashes (free tier, off without a DSN), with only the method, path and request id attached. Free hosts keep logs for a very short time, so a log alone is easy to miss.
42. **The server cleans up after absent drivers.** A trip silent for 30 minutes is ended at its last fix and labelled as automatic. The end is atomic, so several servers can run the job and each trip is closed and announced once. GPS history is trimmed to 90 days in small batches so the free database doesn't fill.
43. **A GPS jump no bus could make is refused, but only against a recent fix.** Above 45 m/s since a fix less than two minutes old, it's a glitch or a spoof. After a longer gap it is accepted, so one bad reading can never make all later correct ones look like jumps.
44. **A standing bus says "still here"; a moving one is never faked.** If the last fix said the bus was at rest, the page repeats that position every 10 s (up to 15 minutes) so a bus parked at a stop doesn't drift to "GPS delayed". If the last fix was moving, silence is shown as the real problem it is.
45. **Shutdown is an orderly sequence with a deadline.** Mark draining (so /health goes 503), stop accepting, disconnect sockets, close Redis and the database, exit 0; force-exit after 10 s. Unexpected crashes are logged and reported, then exit 1 so the host restarts a clean process.
46. **A screen that crashes shows a way out.** An error boundary around the app replaces a blank page with a Reload button and a link back to the map.

47. **No Redis in production, by default.** Measured: 6 Redis commands per GPS fix. Upstash's free 500,000 a month would last about 70 hours of one bus driving. A single server needs nothing from Redis (events go straight to its own clients, rate limits are in memory, `/buses` reads Postgres), and all of that was already built and tested as the fallback. Set `REDIS_URL` only when running several servers.
48. **Cheap when idle, because the free database sleeps.** The cleanup job does nothing when no driver has been active (one sweep at boot, one after the last activity). `/ping` answers without touching the database. Pages in a hidden tab stop polling. Without these, a once-a-minute query would keep a scale-to-zero database awake all month and use up its free compute-hours.
49. **The website proxies `/api`, but the live socket connects straight to the server.** Proxying `/api` through Vercel keeps the sign-in cookie on the site's own address, with no cross-site cookie problems. Vercel's proxy carries normal requests but not WebSockets, so `VITE_SOCKET_URL` sends the socket directly to Render.
50. **How many proxies stand in front is a setting, and the dashboard shows what the server sees.** With Vercel in front of Render the real visitor is one hop further back. Getting it wrong would make every student share one rate limit, so Overview prints the address the server sees; compare it with your real IP.
51. **Migrations run at every start; the first admin and the seed are run from your own PC.** Updating is then just `git push`, and nothing depends on shell access to the host. In production the seed never creates the known dev accounts.
52. **The start command uses `exec`.** Otherwise the shell is the main process, the host's shutdown signal never reaches the server, and it is killed instead of finishing cleanly (tested: with `exec` it exits 0).
53. **A waking server is explained, and retried.** After idle a free host takes up to a minute to answer. The map retries every 5 seconds until the first answer and says what is happening after 5.
